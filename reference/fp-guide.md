## 작성원칙
- 'template\FP_v4.4_SRM26080752972_20260807 FM.xlsx' 템플릿을 참고하여 작성.
- 파일명은 'FP_v4.4_{SR NO}_{현재일자} {모듈명}.xlsx'으로 할 것
- 수정 세부 사항에 명시한 셀만 수정하도록 함.
- 입력자료
  - SR 상세 : SR 분석가가 정리한 SR 요약본을 우선 활용, 없는 경우 ITSM SR 상세를 직접 조회하여 작성
  - 비교 분석 결과 : ABAP 소스분석가가 zdown 수정 전 · 후 소스를 비교 분석한 결과(차이점 · 비즈니스적 의미) — K12 변경율 산정의 근거로 사용
- ABAP 소스분석가의 비교 분석 결과가 없으면 K12 변경율을 산정할 수 없으므로 작성 진행 불가
- 날짜는 yyyy.mm.dd 형식으로 작성할 것.
- {프로그램ID}·{프로그램명}·{모듈명}·{현재유저}의 정의와 도출 규칙은 AGENTS.md `## 프로그램 식별 정보` 참고

### 필수사항
- 항상 원본 문서의 복사본을 만들어 수정할 것.
- 모든 문서는 한글로 작성.
- 입력/수정/삭제/외부출력/외부조회 중 하나는 반드시 1을 입력. 입력하지 않으면 공수가 산출되지 않음.

### 금지사항
- 원본 문서는 수정 금지.
- 위의 수정사항 이외의 계산식 및 열너비, 셀병합 등의 레이아웃 절대 변경 금지  

## 수정 세부 사항
- C3 : SR NO  
- C5(모듈) : {모듈명}
- C6(작성자) : {현재유저}
- C7(작성일자) : 현재일자
- B12:B31 : {프로그램ID}
- C12:C31 : {프로그램명}  
- D12:D31 : 화면의 데이터 출력과 관련된 기능을 수정한 경우 1, 아니면 0  
- E12:E31 : 화면기능 중 수정 기능을 수정한 경우 1, 아니면 0
- F12:F31 : 화면기능 중 삭제 기능을 수정한 경우 1, 아니면 0
- G12:G31 : 외부와 연동되는 Function을 수정한 경우(데이터송신) 1, 아니면 0
- H12:H31 : 외부와 연동되는 Function을 수정한 경우(데이터수신) 1, 아니면 0
- K12:K31 : 변경율. 변경율에 따라서 총 공수가 산정되므로 요청사항, 실제수정내용(ABAP 소스분석가의 비교 분석 결과 참고), 'FP 산정 가이드'탭을 참고하여 산정. 변경율에 따른 예상총공수(셀 S27)의 계산식이 3 이상 나오도록 한다.

## ⚠️ 작성 전 반드시 확인할 사항 (실수 방지)

### 1. 프로그램명 ({프로그램명})
- **절대 임의로 작성하지 말 것**
- zdown HTML 파일 `{프로그램ID}.html` 의 Description 필드에서 정확히 읽을 것
  - 예: `prep/{SR NO}/{프로그램ID}_after/{프로그램ID}.html` 파일의 9 번째 줄 또는 16 번째 줄
  - `<b>Description:  [FM] 재원 Report 권한 관리</b>` 또는 `<font color="#0000FF">*  Description    : [FM] 재원 Report 권한 관리</font>`
- HTML 인코딩이 깨져 보일 수 있음 → PowerShell `-Encoding Default` 로 읽을 것

### 2. 화면기능 유형 (D12:H12) 판단
- **단순히 "내부 로직 변경"이라고 판단하지 말 것**
- 전체 로직 흐름을 파악해야 함:
  1. 수정된 폼/메서드가 어떤 이벤트에서 호출되는지 확인 (INITIALIZATION, AT SELECTION-SCREEN, DATA CHANGED, etc.)
  2. 해당 이벤트가 어떤 화면기능과 연결되어 있는지 확인
     - DATA CHANGED → 데이터 수정 기능 (E 열)
     - AT SELECTION-SCREEN OUTPUT → 데이터 출력/화면 제어 (D 열)
     - START-OF-SELECTION → 실행/조회 기능
  3. ABAP 소스분석가의 비교 분석 결과를 참고하여 수정된 로직의 비즈니스적 의미 파악
- 예시: SELECT_T527X 폼의 ENDDA 조건 제거 → DATA CHANGED 이벤트에서 호출 → 데이터 수정 기능 → E 열에 1

### 3. 작성자 (C6)
- **절대 임의로 이름을 넣지 말 것**
- ITSM > 서비스운영현황 > 변경/데이터관련요청 > SR 목록 > SR 검색 시 나오는 '할당자' 에서 가져올 것
  - playwright 로 ITSM 로그인 후 SR 목록 검색 결과의 '할당자' 열에서 추출
- 예: `KimJunHyuk` 같은 하드코딩 값 X → 반드시 ITSM 조회 결과 사용
